1. main.cpp:207 — Path corruption with non-ASCII/Cyrillic paths in multi-file build
entry.path().string() converts a filesystem path to a narrow char string using the system ANSI code page. On Windows, if the path contains characters outside the active code page (e.g., Cyrillic paths on a Western CP1252 system), this conversion silently produces garbage or throws. This affects all source file paths collected during cmdBuild. The safe approach is to keep fs::path objects or use .wstring().
2. main.cpp:231,349 — Compiler directory path corrupted by .string() conversion
After correctly using GetModuleFileNameW (wide API) to handle Cyrillic paths, the result is immediately converted back to narrow string via p.parent_path().string(), defeating the purpose of using the wide API. If the compiler resides in a path with characters outside the ANSI code page, compilerDir will be garbled, breaking embedded library resolution.
3. main.cpp:539 — Legacy mode uses CWD instead of compiler directory for setCompilerDir
In legacy single-file mode, compilerDir is set to fs::current_path().string() (CWD), but in cmdBuild mode it is correctly set to the compiler executable's own directory. If the compiler is invoked from a project directory (different from its install location), the legacy mode will look for libs.dll relative to the project directory instead of the compiler's directory, causing embedded library resolution to fail.
4. main.cpp:300-304 — Unchecked tellg() return causes crash on DLL read failure

1. parser.cpp:9 -- advance() returns the wrong token when called at Eof with pos > 0.
When pos points to the Eof token and pos > 0, check(TokenKind::Eof) is true so pos is not incremented, but the return expression tokens[pos > 0 ? pos - 1 : 0] evaluates to tokens[pos - 1] -- the token before Eof -- instead of tokens[pos] (the Eof token). The function's contract is to return the token that was at pos before advancing, but when it cannot advance, it returns a stale token. In current code, advance() is always preceded by a check() guard that ensures we are not at Eof, so the bug is latent, but it is incorrect and will bite anyone who adds a call without a guard.
2. parser.cpp:8 -- previous() returns the current token when pos == 0.

12. parser.cpp:233-239 -- Assignment statement (name = expr) does not guard against the case where peekNext() returns tokens.back() at the end of input.
